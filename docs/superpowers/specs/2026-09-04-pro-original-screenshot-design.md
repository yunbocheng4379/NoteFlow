# Pro 专属原片截图设计

## 背景

NoteFlow 的“原片截图”笔记格式会触发完整视频下载、视频抽帧和截图生成，当前普通用户可以通过前端表单或直接调用生成接口使用该功能。本次将“原片截图”设为 Pro 会员专属，同时保持现有视频理解和截图依赖逻辑。

## 目标

- 免费用户仍能在“笔记格式”下拉菜单中看到“原片截图”，但该选项不可选，并明确显示 Pro 专属标识。
- 免费用户点击锁定选项时得到升级引导，不改变当前已选格式。
- Pro 用户可继续选择和使用“原片截图”。
- 后端对单个生成和批量生成接口统一执行权限校验，防止绕过前端提交请求。
- 计费预览与实际生成保持一致；未通过权限校验的截图请求不得创建任务或扣除电力。

## 非目标

- 不改变“视频理解”开关的现有模型能力校验。
- 不改变“原片跳转”、目录和 AI 总结的会员权限。
- 不新增会员套餐、支付流程或数据库字段。
- 不扩展浏览器扩展和小程序端，本次范围聚焦主 React Web 端及其生成 API。

## 方案

### 前端

在 `NoteForm` 的笔记格式多选下拉中，将 `screenshot` 的禁用条件扩展为“非 Pro 或未开启视频理解或所选模型不支持视觉”。免费用户点击该选项时：

1. 不调用 `onChange`，因此不会把 `screenshot` 写入表单值。
2. 显示锁定/Pro 视觉提示。
3. 弹出提示并提供跳转 `/upgrade` 的升级入口；若现有通知组件不支持操作按钮，则使用带升级链接的轻量提示组件或等价的现有 UI 模式。

Pro 用户仍需满足现有视频理解和视觉模型条件；不满足时继续显示现有“需开启视频理解”提示，避免混淆两种限制。

### 后端

复用 `app.services.kb_permissions.require_pro` 的订阅判定方式，在 `generate_note` 和 `generate_notes_batch` 的请求处理早期检查 `data.format` 是否包含 `screenshot`。非 Pro 用户返回统一的业务错误：“原片截图为会员功能，请升级 Pro”，不进入模型检查、计费、建任务和后台执行流程。

权限检查放在生成入口而不是 `NoteGenerator` 内部，以覆盖单个和批量 API，同时保持服务层可被已有内部流程复用。有效订阅的判断继续以 `active_subscription_id` 为准，沿用项目当前会员模型。

### 计费预览

前端不会向免费用户提交 `screenshot` 格式，因此现有预览不会展示截图附加费用。后端生成接口继续独立计算并扣费；权限校验先于扣费，保证非法请求不会产生电力流水。

## 错误处理

- 前端会员状态尚未加载时按非 Pro 处理，避免在权限未知时开放高成本功能；余额刷新成功后自动恢复可用状态。
- 后端权限拒绝使用项目现有业务错误响应格式，前端沿用请求层错误对象展示消息。
- 订阅过期但前端缓存仍显示 Pro 时，后端校验仍是最终准入条件。
- 批量生成同样在任何计费和建任务操作前拒绝截图请求。

## 测试

- 后端：免费用户携带 `screenshot` 调用单个生成接口时被拒绝，且不进入扣费/任务流程。
- 后端：免费用户携带 `screenshot` 调用批量生成接口时被拒绝。
- 后端：Pro 用户的单个和批量请求不因该校验被拒绝。
- 前端：免费用户点击截图选项不会修改格式值，并触发升级引导。
- 前端：Pro 用户在满足视频理解与视觉模型条件时可以选中截图。
- 回归：现有视频理解关闭或模型不支持视觉时，截图仍保持原有禁用行为。

## 验收标准

1. 免费用户在截图选项旁看到 Pro 锁定提示，点击可进入升级页。
2. 免费用户无法通过正常 UI 选中截图，也无法通过直接构造请求绕过后端权限。
3. Pro 用户的截图生成流程和现有截图计费逻辑保持可用。
4. 相关后端测试、前端 lint/build 或对应测试命令通过。
