# 笔记风格 AI 初筛模型配置设计

## 目标

复用系统现有的模型供应商和模型配置，让管理员可以选择一个专门用于笔记风格内容安全初筛的模型。用户提交笔记风格后，系统调用该模型分析标题、简介和提示词，并把风险等级、风险类别、摘要和修改建议展示给管理员；是否通过、上架或驳回仍由管理员人工决定。

## 方案

在数据库增加系统级配置项，保存安全检测模型的 `provider_id` 和 `model_name`，不复制 API Key。管理员在现有“模型配置”节点看到“笔记风格安全检测模型”卡片，可从已启用的供应商及其已配置模型中选择并保存。

提交审核时，服务端先执行现有本地明显风险词规则；未命中时调用管理员选定的大模型。模型要求返回 JSON，服务端对返回结果做容错解析和字段归一化。AI 结果只写入当前待审核版本及审核记录，不改变人工审核状态；未配置、调用失败或返回格式异常时，仍保持“待审核”，并明确提示管理员人工处理。

## 管理员展示

管理员详情继续展示 AI 初筛状态和风险等级，同时补充风险类别、AI 摘要和修改建议。列表保留简短状态，详情展示完整结果。切换检测模型只影响后续提交，历史版本保存当时的 AI 结果。

## 安全与失败策略

- 只有管理员可以读取和修改安全检测模型配置。
- 只能选择启用的供应商和已存在的模型；停用或删除后不自动放行内容。
- AI 不能自动通过、自动上架或自动驳回。
- 未配置模型、调用超时、供应商错误、返回非法 JSON 时，状态保持 `PENDING_REVIEW`，并将错误原因写入 AI 摘要。
- API Key 继续由现有供应商表管理，不通过新接口返回。

## 验证范围

覆盖配置读写和权限、模型有效性校验、AI JSON 解析、未配置/失败保留人工审核、成功结果写入版本和管理员详情，以及前端选择和保存流程。完成后运行后端编译、前端类型检查、前端构建和至少三轮独立的完整流程测试。
