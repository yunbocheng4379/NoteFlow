# NoteFlow 微信小程序核心闭环设计

## 1. 目标与范围

本次改造面向 `noteflow-miniprogram/`，目标是在微信小程序内交付一条稳定、舒适且与桌面端视觉统一的核心使用闭环：

1. 微信一键登录为主，邮箱/密码登录为兜底。
2. 粘贴视频链接，识别平台并获取视频预览。
3. 选择模型与笔记风格，创建笔记生成任务。
4. 任务列表查看生成状态，成功后进入笔记详情。
5. 在详情页阅读 Markdown 笔记，并基于当前笔记进行 AI 问答。
6. 在个人中心查看用户状态、余额、生成统计和退出登录。

本版本不纳入充值/会员、订单、合集、知识库、闪记卡等分包能力；不新增小程序专用后端接口，继续复用现有 FastAPI `/api` 接口。

工作区已有其他未提交修改，本次实现只聚焦 `noteflow-miniprogram/` 及本设计文档，避免覆盖无关工作。

## 2. 产品定位与视觉方向

小程序定位为 NoteFlow 的轻量移动工作台：打开即能开始记录，生成后能快速阅读和追问。

视觉采用“轻量工作台”：暖白底、白色内容卡片、深青绿主色，辅以克制的珊瑚色错误提示。与桌面端沿用同一套主色，不使用 emoji 作为正式导航或功能图标。

## 3. 信息架构

主包保留 3 个 Tab：

- **首页**：链接输入、平台识别、视频预览、模型/风格选择、任务创建、生成中状态。
- **笔记**：任务列表、状态筛选、下拉刷新、进入详情。
- **我的**：登录状态、用户信息、余额、统计、可用账户入口、退出登录。

详情页和登录页为非 Tab 页面：

- **笔记详情**：标题与来源、笔记阅读、AI 问答、分享/复制/删除等轻量操作。
- **登录**：微信登录主入口、邮箱/密码登录表单、协议说明。

## 4. 核心数据流

### 4.1 会话恢复

```text
小程序启动
  ├─ 本地无 access_token → 保持访客态
  └─ 有 access_token → 后台请求 /api/auth/me
       ├─ 成功 → 同步全局 userInfo / 登录态
       └─ 401/无效 → 清除 token，回到访客态
```

请求层统一从同一处读取 token，所有页面通过全局会话状态或事件刷新 UI。401 不触发不存在或不稳定的刷新接口循环；统一清除本地会话并在当前动作需要权限时引导重新登录。

### 4.2 笔记生成

```text
输入 URL
  → 客户端平台识别
  → POST /api/video_info
  → 展示标题/封面/平台/时长
  → 选择模型与风格
  → POST /api/generate_note
  → 读取 task_id
  → GET /api/task_status/{task_id}，间隔 3 秒轮询
  → SUCCESS → 进入 /pages/note-detail/note-detail?id=...
```

实现时以实际后端字段为准：生成接口参数使用 `video_url`、`platform`、`model_name`、`provider_id`、`style` 等后端 `VideoRequest` 字段；后端成功响应返回 `task_id`。现有首页中不存在的 `noteApi.createTask` 必须改为现有服务层的 `generateNote`，并补齐参数映射。

### 4.3 笔记问答

```text
进入 AI 问答
  → POST /api/chat/index（若尚未索引）
  → GET /api/chat/status?task_id=...
  → indexed 后 POST /api/chat/ask
  → 使用非流式响应渲染完整回答
```

小程序第一版使用非流式 `/api/chat/ask`，避免在基础闭环中引入 SSE 适配。问答历史保存在当前详情页状态中；页面重新进入时从空会话开始，不额外扩展后端会话模型。

## 5. 页面与组件设计

### 5.1 首页

页面结构：品牌标题与余额入口、链接输入卡、视频预览卡、模型/风格配置卡、主生成按钮、生成中状态卡、最近任务摘要。

交互规则：

- 输入发生变化时清除旧预览和错误；短延迟后自动解析。
- 支持平台由 `platform-detector` 统一判断；不支持时在输入卡下方显示明确错误。
- 未登录用户可以浏览和解析，但点击生成时跳转登录页。
- 生成中将主按钮替换为进度卡，显示当前状态和“查看任务”入口。
- 生成成功后进入详情页；失败保留任务状态和可重试入口。

### 5.2 笔记列表

页面结构：标题、搜索入口、状态筛选（全部/生成中/已完成/失败）、任务卡列表、加载和空状态。

任务卡显示顶部状态线、视频标题、平台、时间、状态和必要的进度。列表从 `/api/tasks` 获取；进入页面刷新，下拉触发重新加载。进行中任务复用轮询管理器更新状态，终态停止轮询。

### 5.3 笔记详情

页面结构：标题与来源信息、分段控制（笔记/AI 问答）、Markdown 阅读区、固定底部操作区。

- 笔记内容复用现有 Markdown viewer，统一标题、列表、引用、代码块、图片代理样式。
- 问答回答靠左、用户问题靠右；空状态提示“基于这篇笔记，问我任何问题”。
- 发送问题前校验登录、任务 ID、问题非空和模型配置；失败保留问题并提供重试。
- 第一版底部操作只保留分享、复制和删除，非核心能力不占用主阅读界面。

### 5.4 我的

登录态展示头像/昵称、余额和三项统计；未登录态展示清晰登录卡，不渲染空统计。菜单仅保留本版本可用入口：账号信息、我的笔记、余额与用量、帮助与反馈、退出登录。

### 5.5 登录

```text
NoteFlow
把视频，变成可复习的笔记

[ 微信一键登录 ]

──── 其他方式 ────

账户（邮箱/用户名/手机号）
密码
[ 登录 ]
注册 / 忘记密码
```

- 微信入口执行 `wx.login()`，调用 `/api/auth/wechat-login`。
- 邮箱密码兜底调用 `/api/auth/login`，后端请求体实际字段为 `{ account, password }`，不是 `{ email, password }`。
- 成功响应当前后端使用 `token` 和 `user`；客户端统一兼容旧字段 `access_token`，并把 token 写入统一会话存储。
- 登录失败展示后端返回的可读错误，避免只显示“登录失败”。

## 6. 接口与客户端边界

服务层集中封装：

- `auth.js`：登录、微信登录、当前用户、登出和会话清理。
- `note.js`：视频预览、生成、任务状态、任务列表、删除和标题更新。
- `model.js`：供应商、模型、笔记风格。
- `chat.js`：索引、索引状态、非流式问答。
- `profile.js`：资料与余额/统计所需信息。

`utils/request.js` 负责：基地址拼接、Bearer 注入、ResponseWrapper 解包、网络错误转换、401 会话清理、可选 toast 抑制和 GET 去重。

环境配置必须支持开发、局域网真机和生产地址切换；默认值不能继续使用仅开发者机器可访问的 `http://localhost:3015`。小程序真机联调要求后端域名完成微信合法域名配置，开发工具可按项目设置放宽校验。

## 7. 错误、空状态与恢复策略

| 场景 | 页面表现 | 恢复动作 |
| --- | --- | --- |
| 网络异常 | 页面内显示连接失败 | 点击重试 |
| 链接不支持 | 输入框下方显示平台/格式错误 | 清除并重新输入 |
| 视频解析失败 | 预览卡显示失败原因 | 重试解析 |
| 未登录提交 | 保留首页输入状态 | 去登录，成功后回到首页 |
| 生成失败 | 任务卡显示原因 | 使用原参数重试 |
| token 失效 | 清理会话，不循环刷新 | 当前权限动作重新登录 |
| Markdown 为空 | 详情页显示内容异常 | 返回列表或重新加载 |
| 问答失败 | 保留用户问题和历史消息 | 重新发送 |

所有空状态都提供下一步动作，错误文案使用用户能理解的动作语言，不暴露堆栈或内部实现名。

## 8. 测试与验收

实现阶段按测试先行处理以下纯逻辑单元：

1. 请求响应解包：成功、业务错误、HTTP 401 和网络异常。
2. 登录响应归一化：`token/access_token` 兼容与会话写入/清理。
3. 平台识别：Bilibili、YouTube、抖音、快手、不支持链接。
4. 任务状态映射：pending、进行中、SUCCESS、FAILED、TIMEOUT。
5. 生成请求参数映射：小程序表单字段转换为后端 `VideoRequest` 字段。

验收条件：

- 微信开发者工具中三 Tab 可打开，页面无横向溢出，点击区域可用。
- 配置正确后端地址，微信登录或邮箱密码登录可完成，会话可恢复，失效 token 不死循环。
- 视频解析、任务创建、3 秒轮询、成功详情和失败重试可联通。
- 笔记详情 Markdown 可读，AI 问答能完成索引后调用 `/api/chat/ask`。
- 任务列表支持刷新、状态筛选、进入详情；个人中心能显示登录态并退出。
- 运行小程序侧可执行的测试、静态检查和构建/打包验证，记录实际结果；不能用“应该可以”替代命令输出。

## 9. 非目标

- 不修改桌面端现有页面和后端业务逻辑，除非联调发现统一接口本身存在阻塞核心闭环的缺陷。
- 不在本轮实现充值支付、会员、订单、合集、知识库、闪记卡和完整流式问答。
- 不引入新的 UI 组件库；优先修复和复用现有小程序组件，减少运行时和包体复杂度。
