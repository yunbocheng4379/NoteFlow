# 订单记录软删除设计

## 目标

允许用户从订单记录页面隐藏已关闭订单，同时保留数据库中的完整订单记录，确保支付对账、权益流水、退款审计和管理查询不受影响。

本次范围仅包含已关闭订单。已支付、待支付和已退款订单不能被用户隐藏。

## 方案

在 `orders` 表增加可空字段 `hidden_at`：

- `NULL`：用户可见；
- 非 `NULL`：用户已隐藏，记录隐藏时间。

使用时间字段而不是布尔字段，便于审计、排查和后续恢复。

## 后端行为

新增接口：

```text
POST /api/billing/order/{order_no}/hide
```

接口规则：

1. 必须登录。
2. 只能操作当前用户自己的订单。
3. 订单状态必须为 `CANCELLED`。
4. 已隐藏订单重复调用保持幂等，返回成功。
5. `PAID`、`PENDING`、`REFUNDED` 订单返回业务错误。
6. 不删除订单行，不修改金额、支付流水、订单状态或用户电力。

订单列表默认增加 `hidden_at IS NULL` 条件，并且分页总数同步排除已隐藏订单。已隐藏订单按普通用户“订单不存在”处理；支付回调、对账、管理员查询不依赖用户可见性字段。

## 前端行为

在订单列表中，仅对“已关闭”订单显示“移除记录”操作：

1. 用户点击后弹出确认提示。
2. 请求隐藏接口。
3. 成功后刷新当前订单列表，并提示“记录已移除”。
4. 失败时保留订单并展示错误提示。

“移除记录”只影响当前用户的订单列表，不代表物理删除。

## 数据迁移与安全

新增 SQL 迁移文件：

- 为 `orders` 增加 `hidden_at DATETIME NULL`；
- 使用字段存在性判断，支持重复执行；
- 不修改历史订单的可见性，历史记录默认继续显示；
- 生产执行前备份数据库。

## 测试与验收

后端验证：

- 字段迁移可重复执行；
- 已关闭订单可隐藏并保留数据库记录；
- 已支付、待支付、已退款订单不能隐藏；
- 其他用户订单不能隐藏；
- 隐藏后订单列表与总数不再包含该订单；
- 重复隐藏保持幂等。

前端验证：

- 已关闭订单显示“移除记录”；
- 其他状态不显示该操作；
- 成功后订单从列表消失；
- 生产构建通过。

## 不在本次范围内

- 物理删除订单；
- 用户端恢复已隐藏订单；
- 管理后台订单回收站；
- 退款流程；
- 修改支付回调或电力流水记录。
