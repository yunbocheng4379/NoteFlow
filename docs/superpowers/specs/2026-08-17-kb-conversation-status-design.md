# 知识库历史问答执行状态与未读提示设计

## 背景

知识库左侧历史会话目前仅支持持久化的 `is_unread` 红点。用户在某个会话中发起流式问答时，历史列表无法指出哪个会话正在执行；如果用户切换到其他会话，回答完成后也无法明确提示原会话有新的结果。

## 目标

- 问答执行期间，在对应历史会话右侧显示灰色旋转图标。
- 回答完成后，如果用户已切换离开该会话，则显示现有红色未读点并持久化 `is_unread`。
- 如果用户始终停留在发起问答的会话中，则不生成红色未读点。
- 切换历史会话时，流式回答不能写入错误的会话。
- 执行状态和流式草稿仅保留在当前浏览器标签页内；刷新页面后不恢复执行中的临时状态。

## 非目标

- 不增加数据库字段。
- 不修改知识库 SSE 协议和后端问答流程。
- 不改变现有手动“标记为未读/已读”、置顶、重命名和删除行为。
- 不实现跨标签页同步或后端任务恢复。

## 设计

### 1. Store 状态

在 `useKnowledgeBaseStore` 中增加当前标签页临时状态：

- `processingConversationIds`：按会话 ID 记录正在执行的问答。
- `streamingDrafts`：按会话 ID 保存本次问答的 assistant 草稿，包括正文、思考过程和引用来源。

新增或调整面向会话的操作，使流式回调始终携带目标 `conversationId`。回调更新目标草稿；只有目标会话当前 active 时，才同步到右侧 `messages`。这样用户切换会话后，原请求仍可继续执行，但不会污染当前会话。

切换会话时加载后端消息；如果目标会话仍在执行，则把对应草稿叠加到消息末尾。切回正在执行的会话不会重新发起请求。

### 2. 问答时序

1. 发送问题时固定本次 `conversationId`，加入执行中状态并初始化 assistant 草稿。
2. `sources`、`reasoning`、`delta` 事件按会话 ID 更新草稿；active 会话实时显示，非 active 会话仅缓存。
3. 收到 `done` 或发生请求异常时，均结束执行状态，避免旋转图标残留。
4. 执行结束时检查目标会话是否仍为 active：
   - 是：不设置 `is_unread`。
   - 否：调用现有会话更新接口设置 `is_unread: true`。
5. 失败结果也属于已结束的会话结果：如果用户已离开目标会话，则显示未读点，回来后可查看错误提示。

### 3. 列表视觉状态

历史会话项右侧保留固定宽度的状态槽位，避免图标切换造成标题跳动：

- 执行中：`LoaderCircle`，中性灰色，使用 `animate-spin`。
- 非执行中且 `is_unread`：沿用现有红色小圆点和标题加粗。
- 无状态：不显示图标。

执行中状态优先于未读状态。active 背景、置顶图标、右键菜单和现有会话排序不变。

### 4. 异常与生命周期

- SSE 正常结束或异常结束都清除执行中状态。
- 网络或服务错误沿用现有错误消息和 toast 展示逻辑，并保留错误内容作为当前 assistant 结果。
- 刷新页面后临时执行状态和草稿不恢复；后端已经落库的消息以及持久化的 `is_unread` 仍通过现有接口加载。
- 删除会话时同时清除该会话的执行状态和草稿，避免删除后残留列表状态。

## 验证标准

1. 在会话 A 提问，A 显示转圈；回答完成且仍停留在 A，不显示红点。
2. 在会话 A 提问后切换到 B，A 在执行中显示转圈，完成后转为红点；切回 A 后红点消失。
3. 执行过程中切回 A，不重复请求，草稿继续显示并正常收尾。
4. 生成失败时转圈消失；离开 A 时显示未读提示。
5. 刷新页面后临时转圈不恢复，已落库消息和持久化未读状态正常恢复。
6. 执行过程中多次切换会话，回答内容不会写入其他会话。

实现后运行 `pnpm build` 和 `pnpm lint`，并对上述交互场景做代码级检查。
