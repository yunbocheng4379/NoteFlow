# 账单额度订单与联系客服设计规格

**日期：** 2026-08-20
**状态：** 已经用户确认，待编写实现计划

## 1. 目标与范围

本次改动覆盖两个独立但同批上线的功能：

1. 账单与额度中的订单生命周期管理：
   - 充值和会员订阅共用一个待支付订单名额；
   - 待支付订单 15 分钟后自动关闭；
   - 页面实时显示剩余时间；
   - 支持用户手动取消订单；
   - 关闭记录保留；
   - 一次性清理当前用户已有的历史待支付订单。
2. 联系客服：
   - 关于页面增加明确的联系客服入口；
   - 复用现有“企业定制 / 私有化部署”二维码；
   - AI 客服命中客服类关键词时，直接展示固定客服回复和二维码，不调用 AI。

本次不实现自助退款。退款方案另行设计。

## 2. 当前系统约束

- 后端：FastAPI + SQLAlchemy + MySQL。
- 前端：React + TypeScript + Vite + Tailwind。
- 订单模型已经支持 `PENDING`、`PAID`、`CANCELLED`、`REFUNDED`。
- `CANCELLED` 作为数据库状态，前端中文显示为“已关闭”，不新增 `CLOSED` 枚举，减少数据库迁移风险。
- 关于页面已经引用 `src/assets/enterprise-service-qr.png`，客服功能复用该资源。
- AI 客服当前通过 `AssistantPanel` 调用流式 AI 接口；关键词拦截放在发送请求之前。

## 3. 订单生命周期设计

### 3.1 订单有效期

在 `orders` 表新增：

```text
expires_at DATETIME NULL
```

创建充值或订阅订单时：

```text
expires_at = created_at + 15 分钟
```

只有 `PENDING` 订单需要检查有效期。以下状态不再过期处理：

- `PAID`
- `CANCELLED`
- `REFUNDED`

对已有订单执行迁移时：

- 已支付、已取消、已退款订单的 `expires_at` 保持为空；
- 历史 `PENDING` 订单的 `expires_at` 根据 `created_at + 15 分钟` 回填；
- 已超过有效期的历史 `PENDING` 订单在迁移或首次访问时转为 `CANCELLED`，写入 `cancelled_at`。

### 3.2 每个用户只能有一个待支付订单

充值和订阅共用同一个限制：

```text
同一个 user_id 下最多一个 status=PENDING 且未过期的订单
```

创建订单的事务流程：

1. 锁定当前用户行，防止同一用户并发创建订单；
2. 关闭该用户所有已过期的 `PENDING` 订单；
3. 查询该用户是否仍有未过期的 `PENDING` 订单；
4. 如果存在，返回业务错误，不创建新订单；
5. 如果不存在，创建新订单并写入 `expires_at`；
6. 提交事务。

错误文案：

```text
您已有一个待支付订单，请先完成支付或取消原订单
```

不能只依赖前端判断，后端必须是最终约束。

### 3.3 自动关闭

实现双层保障：

- 后台定时任务：应用启动后每 60 秒扫描并关闭过期 `PENDING` 订单；
- 请求兜底：订单列表、订单详情、创建订单、继续支付、取消订单接口执行前，先关闭当前用户已过期订单。

关闭操作：

```text
status: PENDING -> CANCELLED
cancelled_at: 当前时间
expires_at: 保留
```

关闭不会产生电力流水，不会发放权益，不会调用支付宝/微信退款。

定时任务需要在应用关闭时取消，避免后台任务泄漏。关闭异常记录日志，但不能影响主请求。

### 3.4 手动取消

新增登录接口：

```http
POST /api/billing/order/{order_no}/cancel
```

规则：

- 只能取消当前用户自己的订单；
- 只能取消 `PENDING` 订单；
- 已支付订单不能取消；
- 已关闭订单重复取消应返回幂等成功或“订单已关闭”，不能抛出 500；
- 取消后保留订单记录；
- 支付凭证不再允许继续使用。

### 3.5 支付安全边界

继续支付和支付宝/微信异步通知都必须再次检查订单状态：

- `CANCELLED` 订单不能生成新的支付凭证；
- 已过期但尚未被定时任务处理的订单，接口内先关闭再拒绝支付；
- 异步通知收到已关闭订单时不能发放电力或会员权益；
- 已支付订单的异步通知保持幂等，不重复发放权益。

## 4. 后端 API 数据结构

订单序列化新增：

```json
{
  "expires_at": "2026-08-20T15:30:00",
  "remaining_seconds": 842
}
```

`remaining_seconds` 由后端按当前时间计算，前端仅用于初始化和展示；前端不能以它作为支付安全判断依据。

订单状态文案：

| 数据库状态 | 界面文案 |
| --- | --- |
| PENDING | 待支付 |
| PAID | 已支付 |
| CANCELLED | 已关闭 |
| REFUNDED | 已退款 |

## 5. 前端账单页面

### 5.1 待支付展示

待支付订单展示：

- 状态“待支付”；
- 倒计时“剩余 14:59”；
- “继续支付”；
- “取消订单”。

倒计时规则：

- 每秒递减；
- 页面刷新从 `expires_at` 重新计算；
- 倒计时到 0 后停止显示负数；
- 自动刷新订单列表；
- 如果后端已关闭，显示“已关闭”；
- 用户在其他页面完成支付后，回到账单页要能刷新为“已支付”。

### 5.2 取消交互

点击“取消订单”后：

1. 弹出确认提示；
2. 用户确认后调用取消接口；
3. 成功后刷新当前订单页；
4. 显示“订单已关闭”；
5. 保留该订单记录。

取消期间按钮禁用，防止重复请求。

### 5.3 创建订单反馈

如果后端返回“已有待支付订单”：

- 不创建新的支付弹窗；
- 提示用户先去订单记录完成支付或取消原订单；
- 订单页提供清晰的操作入口。

## 6. 当前用户历史订单清理

这是一次性运维操作，不做成对所有用户开放的删除接口。

执行顺序：

1. 登录当前生产数据库并备份；
2. 根据当前用户的订单记录或用户标识解析唯一 `user_id`；
3. 只查询该 `user_id` 下的 `PENDING` 订单并记录数量与订单号；
4. 用户确认目标无误后删除这些历史 `PENDING` 订单；
5. 不删除 `PAID`、`CANCELLED`、`REFUNDED` 订单；
6. 删除后重新查询确认数量为 0；
7. 在部署报告中记录备份文件、目标用户、删除数量和订单号摘要。

不允许使用无 `user_id` 条件的全表删除。

## 7. 联系客服设计

### 7.1 关于页面

在现有“联系我们”区域增加单独的“联系客服”视觉入口，复用：

```text
NoteFlow_frontend/src/assets/enterprise-service-qr.png
```

点击后打开现有二维码预览 Dialog。文案：

```text
联系客服
遇到支付、订单或使用问题，可扫码添加客服微信
请备注“客服”并附上账号或订单号
```

企业定制二维码仍可保留原有卡片，避免影响原有企业咨询入口。

### 7.2 AI 客服关键词拦截

匹配前先做：

- 去除首尾空格；
- 转换为小写用于英文匹配；
- 中文使用直接包含判断；
- 只检查当前问题。

关键词集合：

```text
客服
人工
人工客服
联系客服
售后
技术支持
支付问题
退款
怎么联系
联系工作人员
```

命中后不调用 `askAssistantStream`，直接加入固定助手消息：

```text
您好，如需人工客服，请扫码添加客服微信。
请备注“客服”，并附上您的账号、订单号或问题截图，我们会尽快处理。
```

消息中展示 `enterprise-service-qr.png`，支持点击放大。非命中问题保持现有 AI 流式问答。

为了避免用户输入“人工智能”时误触发，可将“人工”匹配限定为：

- 完整问题等于“人工”；
- 或包含“人工客服”“转人工”“联系人工”等客服语境；
- 不单独拦截“人工智能”。

## 8. 退款结论

本次不实现自助退款。

原因：

- 充值电力可能已经部分消耗；
- 会员订阅可能已经生效；
- 电力存在充值、订阅赠送、注册赠送、邀请奖励等来源；
- 没有按来源分批追踪时，无法准确判断可退金额；
- 直接按订单金额退款可能导致用户已经消费权益但仍全额退款。

后续如果要支持退款，建议另立设计：

1. 先增加电力批次或可追溯的账本来源；
2. 规定只退未消耗部分；
3. 明确会员已生效、已使用电力、优惠金额的处理规则；
4. 接入支付宝/微信退款 API；
5. 增加退款申请、审核、退款中、成功、失败状态；
6. 所有退款必须写入审计流水。

当前通过客服人工处理异常支付和特殊退款。

## 9. 测试要求

### 后端测试

至少覆盖：

- 新用户无待支付订单时可以创建；
- 创建充值后不能创建订阅；
- 创建订阅后不能创建充值；
- 过期订单被关闭后可以创建新订单；
- 定时过期任务关闭订单；
- 手动取消只影响当前用户的待支付订单；
- 不能取消其他用户订单；
- 不能取消已支付订单；
- 关闭订单不产生电力流水；
- 关闭订单不能继续生成支付宝支付链接；
- 已关闭订单收到异步通知不发放权益；
- 订单序列化包含 `expires_at` 和剩余秒数。

### 前端测试

至少覆盖：

- 待支付订单显示倒计时；
- 倒计时归零后刷新状态；
- 点击取消后订单变为“已关闭”；
- 新建订单被拒绝时展示已有待支付订单提示；
- 客服关键词命中时展示固定文案和二维码；
- “人工智能”不会误触发人工客服；
- 普通问题仍调用 AI 客服。

### 部署验证

- 数据库迁移成功且可重复执行或明确不可重复；
- 后端健康检查通过；
- 账单页可以加载；
- 创建充值和订阅订单的互斥规则生效；
- 支付回调未受影响；
- 关于页面二维码可显示；
- AI 客服二维码可显示；
- 当前用户历史待支付订单清理数量准确。

## 10. 不在本次范围内

- 自助退款；
- 订单物理删除 API；
- 修改支付宝或微信支付渠道；
- 修改当前充值价格；
- 修改其他用户历史订单；
- 更换客服二维码图片；
- 重构整个 AI 客服系统。
