# 任务列表无合集时创建并加入笔记流程设计

## 背景

用户在任务列表中选择已完成笔记加入合集时，如果账号还没有任何合集，当前弹窗只有“取消”按钮，无法继续完成操作。需要把用户引导到“笔记合集”页面创建合集，并保留本次选中的笔记，在创建成功后自动加入新合集。

## 目标

- 无合集时的“加入合集”弹窗提供“取消”和“去创建”两个操作。
- 点击“去创建”后跳转到 `/collections`，并自动打开“新建合集”弹窗。
- 创建成功后自动把原先选中的任务 ID 加入新合集。
- 加入成功后进入新合集详情页。
- 保持已有合集时的选择、加入和批量加入流程不变。

## 设计

### 跨页面数据传递

不新增全局状态，使用 React Router 的 `location.state` 传递一次性导航上下文：

```ts
{
  openCreate: true,
  taskIds: string[],
}
```

`AddToCollectionDialog` 在无合集状态下点击“去创建”时关闭当前弹窗，并导航到 `/collections`。`CollectionPage` 监听该状态，打开创建弹窗并保存待加入的任务 ID；消费后立即清理路由状态，避免刷新或重复渲染再次打开弹窗。

### 创建与自动加入

创建合集仍通过现有 `useCollectionStore().createCollection` 完成。创建成功后调用现有 `addCollectionItems(created.id, pendingTaskIds)`：

- 没有待加入任务时，行为与普通新建合集一致。
- 有待加入任务且接口成功时，提示加入成功并导航到新合集详情页。
- 合集已创建但加入接口失败时，保留新合集，提示用户加入失败并导航到该合集详情页，用户可从详情页重试。

### 弹窗交互

无合集状态的底部按钮为：

- “取消”：关闭加入合集弹窗，停留在任务列表。
- “去创建”：关闭当前弹窗并跳转到合集页面创建合集。

有合集状态的底部保持现有“取消”按钮，不改变已有加入方式。

## 测试与验证

- 验证相关前端文件的 ESLint 和 TypeScript 检查。
- 执行前端生产构建。
- 使用 `git diff --check` 检查格式问题。

## 范围

本次只修改任务列表加入合集弹窗和笔记合集页面的创建流程，不调整后端接口、不改变已有合集选择 UI，也不处理其他入口的合集创建流程。
