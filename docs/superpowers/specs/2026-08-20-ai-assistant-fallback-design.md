# AI 客服无法回答兜底与人工客服卡片设计

## 背景

NoteFlow 的 AI 客服“小流”目前已经支持用户主动咨询人工客服并展示二维码，但 AI 请求失败时只展示技术错误文本；当产品资料不足时，二维码图片也会按原始尺寸渲染，导致客服卡片在对话面板中占用过大空间。

本次只优化现有 AI 客服，不改变登录、问答接口或二维码资源内容。

## 目标

1. 当 AI 服务异常、模型不可用、余额不足或产品资料不足时，给用户一段友好、安抚情绪的说明。
2. 在上述兜底场景中展示现有人工客服二维码，引导用户联系人工客服。
3. 将问答中的二维码控制在紧凑、清晰、居中的尺寸，适配当前浅色、绿色主题。
4. 保留用户主动询问客服时的现有行为，并避免把普通“不确定”用语误判为无法回答。

## 非目标

- 不引入新的后端 SSE 事件类型。
- 不更换或重新生成二维码资源。
- 不把模型所有模糊措辞都视为无法回答。
- 不改动 AI 客服之外的页面或服务。

## 方案

采用前端统一兜底处理，后端继续返回现有错误语义。

### 兜底内容

在 `assistantSupport.ts` 中集中维护两类判断和内容生成：

- 显式客服咨询：沿用现有客服二维码回复。
- 无法回答兜底：生成友好话术，并插入二维码 Markdown 图片。

无法回答的判断范围限定为：

- 流式请求触发 `onError`；
- AI 正常返回但内容包含现有产品边界中明确的“当前产品资料不足”表达；
- 空回答结束且没有可展示内容。

不根据“可能”“不确定”等通用词语触发兜底，避免误判。

建议用户可见话术：

> 这个问题我暂时还无法准确确认，不想给你错误的答案。别着急，可以联系人工客服帮你进一步处理，添加时备注一下账号和问题，会更快得到帮助：

话术后展示二维码和扫码说明。

### 错误处理流程

1. 用户发送问题后，继续创建一个空的 assistant 消息并显示加载状态。
2. 流式请求触发错误时，不把供应商、余额或请求状态等技术文本直接写入聊天气泡；将当前 assistant 消息替换为统一兜底内容，并停止加载状态。
3. 请求正常完成后，检查最终回答是否为空或是否包含明确的产品资料不足表达；命中时替换为统一兜底内容。
4. 已有 `error` 状态仅用于保留重新发送提示，不影响兜底话术和二维码展示。

为支持“替换当前消息”，在现有 assistant store 中增加最小的 `setLastMessageContent` 能力，不改变消息数据结构。

### 二维码渲染

在 `AssistantMarkdown` 中为 Markdown 图片提供统一渲染属性：

- 最大宽度约 `150px`，最大高度约 `190px`，保持原始比例；
- `display: block`、水平居中；
- 保留清晰度，避免拉伸变形；
- 使用轻微圆角和边框，与现有客服气泡一致；
- 仅约束 AI 客服 Markdown 内的图片，不影响系统其他图片。

由于二维码原图为纵向图片，按最大宽度限制可以同时保留头像、二维码和底部提示文字，并明显降低在对话卡片中的视觉占用。

## 涉及文件

- `NoteFlow_frontend/src/components/assistantSupport.ts`
  - 增加统一的无法回答判断与兜底回复生成。
- `NoteFlow_frontend/src/components/AssistantPanel.tsx`
  - 接入错误和空/资料不足回答兜底。
  - 为 Markdown 图片增加受控渲染属性。
- `NoteFlow_frontend/src/store/assistantStore/index.ts`
  - 增加替换最后一条 assistant 消息内容的方法。
- `NoteFlow_frontend/src/index.css`
  - 增加客服 Markdown 图片的紧凑布局样式。
- `NoteFlow_frontend/src/components/assistantSupport.test.ts`（如项目测试组织允许新增）
  - 覆盖客服咨询识别、兜底文本和资料不足判断。

## 验证标准

- 后端请求失败或流式返回错误时，聊天气泡中出现友好兜底话术和二维码，不出现原始技术错误。
- AI 返回“当前产品资料不足，我不想猜测”时，出现同一套兜底话术和二维码。
- 主动发送“联系客服”等问题时，原有客服回复仍可用。
- 二维码在 AI 客服面板内明显小于当前截图效果，保持完整可识别且不变形。
- 普通包含“不确定”等词语的正常回答不会触发二维码。
- 前端 lint/build 或相关测试通过。
