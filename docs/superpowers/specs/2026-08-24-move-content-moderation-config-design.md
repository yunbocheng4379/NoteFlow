# 笔记风格安全检测模型配置迁移设计

## 目标

将“笔记风格安全检测模型”配置从“AI 模型设置”节点迁移到管理员专用的“笔记风格管理”节点，使配置位置与实际业务职责一致。

## 范围

- 从 `AI 模型设置` 页面移除安全检测模型配置卡片。
- 在 `笔记风格管理` 页面增加同一配置卡片。
- 继续复用现有的模型查询、配置读取和保存 API。
- 保留“未配置”“加载中”“无可用模型”、保存中和失败提示等现有行为。
- 不修改后端接口、数据库结构、审核状态流转或 AI 初筛逻辑。

## 页面设计

“笔记风格管理”页面顶部保留标题、待审核数量和刷新按钮；在审核状态筛选区附近放置“笔记风格安全检测模型”配置卡片。卡片包含当前用途说明、模型下拉选择和“保存检测模型”按钮，视觉上使用现有管理员页面的卡片样式。

管理员保存配置后，该配置继续作为用户提交笔记风格时的 AI 初筛模型，最终是否通过仍由人工审核决定。

## 组件与数据流

保留现有 `ContentModerationConfig` 组件及其状态管理，不复制实现：

1. 组件加载时调用 `contentModerationApi.getConfig()`。
2. 管理员选择已启用的供应商模型。
3. 点击保存时调用 `contentModerationApi.updateConfig(providerId, modelName)`。
4. 保存成功后刷新本地选择并显示成功提示。
5. 笔记风格提交流程继续由后端读取同一份安全检测模型配置。

## 错误与边界处理

- 未选择模型时不发送保存请求，并提示管理员选择模型。
- 模型列表为空时显示“暂无已启用模型，请先配置模型供应商”。
- 加载或保存失败时保留现有错误提示，不阻塞审核列表的其他功能。
- 迁移过程中不删除后端已有配置数据。

## 验证标准

- `AI 模型设置`页面不再渲染该配置卡片。
- `笔记风格管理`页面能正常加载并保存安全检测模型。
- TypeScript 检查、目标文件 ESLint 检查和生产构建通过。
- `git diff --check` 通过。
